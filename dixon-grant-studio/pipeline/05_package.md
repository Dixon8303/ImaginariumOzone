# 05 — Package: Final Assembly

Purpose: turn a self-checked, gate-passed draft (`04_selfcheck.md`) into
the files the client actually submits and the one-page checklist they
use to do it.

## Only after the gate passes

This step never begins on a draft that hasn't cleared `04_selfcheck.md`
with GATE STATUS: PASS. Assembly is not a place to catch remaining
problems — it is formatting and delivery of an already-correct package.

## Deliverable files

1. **Formatted .docx** — the full narrative package (needs statement,
   program narrative, logic model, budget narrative, evaluation plan,
   organizational capacity statement), formatted to the funder's exact
   specifications from the requirements matrix: font, margins, page
   numbering, headers matching the funder's stated section order (not
   the drafting order in `03_draft.md` if the RFP requires a different
   sequence).
2. **PDF** — exported from the final .docx, checked after export for:
   - Page count still within limit (PDF export can shift pagination)
   - All tables (logic model, budget) render without truncation or
     overflow onto a cut-off page
   - Hyperlinks, if any, resolve correctly
   - File named per the RFP's naming convention, if one is specified;
     otherwise `[OrgName]_[FunderProgram]_Application_[Date].pdf`
3. **Budget workbook** (if the funder requires a spreadsheet in addition
   to or instead of a budget narrative) — in the funder's own template
   if one is provided, formulas checked, totals cross-footing to the
   narrative figures exactly.
4. **One-page submission checklist** — see template below. This is the
   last thing the client reads before clicking submit or sealing the
   envelope.

## Delivery to client

Package delivered as: final .docx, final PDF, budget workbook (if
applicable), one-page submission checklist, and the self-check scorecard
from `04_selfcheck.md` — so the client sees exactly how the package
scores against the funder's own rubric before they submit it themselves.
