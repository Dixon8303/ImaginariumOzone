## A. "Emergence: The Digital Rise" (concept)

- **Tagline:** Understand that you are a "Catalyst" influencing a simulation where simple rules evolve into complex civilizations.
- **Core concept:** Complexity emerges from simple rules; **you shape the probabilities, not the people.**
- **Catalyst, not a ruler:** Influence climate, resources, and cosmic events instead of issuing direct commands to individuals. Influence level: *indirect*.
- **The infinite game loop:** Observe → Influence → Wait → Civilization adapts → History changes → Observe again.
- **Five phases of universal evolution:** Reality (physics) · Life (genetics) · Society (culture) · Intelligence (knowledge) · Player interaction.
- **Systems over content:** pre-written scripts and quests are rejected; emergent behaviors and history are the product. "History is generated by emergent behaviors rather than pre-written scripts or quests."

## B. "Emergence: The Interface of Evolution" (interface)

- **Subtitle:** The player is a catalyst shaping probabilities, not a ruler issuing orders.
- **Catalyst Palette:** three slider groups. *Influence Climate* (temperature, storm intensity). *Resource Availability* (one slider per resource). *Mutation Rates* (stable → volatile). Caption: "Influence climate, resource availability, and mutation rates rather than controlling individuals."
- **Core gameplay loop:** Observe → Influence → Wait → Track History, feeding a **Living History** panel: a timestamped list of events, each with a drill-down chevron.
- **Observation View:** "A hybrid visualization of living diagram, flowing particles, and neural network maps."
- **Generative audio feedback:** Harmony (cooperation) versus dissonance (conflict). "The soundtrack evolves in real-time, using harmony to reflect cooperation and dissonance to signal conflict."
- **Time model management:** a high-speed simulation dial (illustrated as 1 real minute = 1 simulated hour). "High-speed simulation continues even when the player is offline."

## C. Derived design commitments

| # | Element | Module | Commitment |
| :-- | :--- | :--- | :--- |
| C1 | "Shape the probabilities, not the people" | DEOS-F03, DEOS-PLAY | The governing sentence of the player role. Formally: no Catalyst Action may write a `Decision` component or override an agent's action choice. Legal targets are Substrate Cell fields, population-level rates (mutation bias), and MemeVector deltas applied to every agent within a radius. A whisper changes what agents believe; it never chooses for them. |
| C2 | Loop verbs | DEOS-PLAY | The canonical core loop is **Observe · Influence · Wait · Adapt · History**. The Host's primary regions map one-to-one: Observation View, Catalyst Palette, Time Control, Chronicle (the "Living History"). No other verb names are used for these regions. |
| C3 | Catalyst Palette families | DEOS-PLAY (`CAT`), DEOS-CORE, DEOS-ECS | The `CatalystAction` kind enumeration must contain the four families: **Climate** (temperature, moisture), **Resource** (Cell energy, material), **Mutation** (a regional multiplier on per-gene mutation probability, realized as the Cell field `mutation_bias`), and **Cosmic** (composite events: meteor, solar flare, drought, flood) that expand deterministically in Stage 1 into primitive field writes while the Input Log stores the single composite record. |
| C4 | Indirect influence with sliders | DEOS-PLAY (`CAT`) | Payloads are continuous Q32.32 magnitudes; cost in Catalyst Budget scales with magnitude and radius; the interface is sliders and regions, never unit orders. |
| C5 | Five phases | DEOS-PLAY, DEOS-PROTO (`EVT`) | **World Phases** are a player-facing progression ladder: Reality → Life → Society → Intelligence, with Player Interaction as the constant fifth. A phase is reached when a threshold Notable Event first occurs in the world (first self-sustaining population; first Institution; first technology discovery). The Protocol emits reserved kind 6 `WORLD_PHASE_REACHED`; it is a derived marker computed from firsts, never a script (GI-7). The ladder also mirrors tick pipeline Stages 2–5 and the ROADMAP phases. |
| C6 | Living History | DEOS-PLAY | Chronicle rows display simulated time derived from the tick (`TICKS_PER_DAY`), and every row drills down to its cause chain: Notable Event → `cause` → Decision Trace (GI-5). |
| C7 | Observation View | DEOS-PLAY | Three required layers, each bound to read-buffer data: **Particles** (`Position2D`, `EnergyState`, `Lifecycle`), **Living Diagram** (`Affiliation`, `InstitutionState`, `TrustEdges` drawn as a graph), **Network Map** (MemeVector similarity and trust topology). Rendering is Host-side; the data contract is Kernel-side. |
| C8 | Generative audio | DEOS-PROTO, DEOS-RT, DEOS-PLAY | The Kernel exposes deterministic per-tick **Affective Signals** through the egress ring as the `WorldMood` record (cooperation, conflict, growth, entropy, population, institutions). The Host maps cooperation to harmony and conflict to dissonance. The player hears the world's state before reading it. |
| C9 | Time model | DEOS-PLAY, DEOS-RT | Attended play uses `SPEED_LEVELS`; "the simulation continues while offline" is delivered either by client-side Acceleration on return or by a server stepping the world continuously. Both produce identical Tick Hashes (GI-4), so this is a hosting decision, not a design one. The infographic's calibration (1 real minute = 1 simulated hour) is illustrative; the registry's `TICKS_PER_DAY` = 3,600 stands until MVS playtesting revises it. |
| C10 | Systems over content | DEOS-F02 Directive 1 and 10, GI-7 | Already binding; the infographic is the public statement of it. |

## D. Registry additions made for these commitments (DEOS.md §5)

- Substrate Cell field `mutation_bias` (Q32.32, default 1.0, range [0.25, 4.0]); written by Stage 1 Catalyst Actions, decays toward 1.0 in Stage 2 at a Core-owned rate; read by Protocol reproduction.
- `WorldMood` egress record: `{ tick: u64, population: u32, institutions: u32, cooperation: Q32.32, conflict: Q32.32, growth: Q32.32, entropy: Q32.32 }`, 48 bytes in a 64-byte slot; values computed by Protocol at the end of Stage 5, emitted by Runtime in Stage 6.
- Reserved `NotableEvent.kind` 6 = `WORLD_PHASE_REACHED` (magnitude = phase index 1–4).
- `CatalystAction` composite kinds ("Cosmic") expand in Stage 1; the Input Log stores the composite record only.
